# ANGELA v20 — Production Security, Migrations & Audit

## Added

- Versioned PostgreSQL migrations under `backend/api/migrations/`.
- `schema_migrations` table and `npm run migrate` runner.
- User `audit_logs` table.
- Admin `admin_audit_logs` table.
- Request IDs (`x-request-id`) on API responses.
- Constant-time comparison for `ADMIN_API_KEY`.
- Admin withdrawal actions now generate audit records.
- API health version updated to v20.

## Deployment order

1. Install dependencies: `npm install`
2. Set production environment variables.
3. Run `npm run migrate`.
4. Start API with `npm start`.
5. Keep `WITHDRAWALS_ENABLED=false` until official launch.
6. Use HTTPS in production and `COOKIE_SECURE=true`.

## Important remaining production hardening

The in-process rate limiter is suitable for a single-instance staging deployment, not a horizontally scaled production cluster. Before scaling beyond one API instance, move rate limiting/session coordination to Redis or another shared store.

`ADMIN_API_KEY` is a transitional admin authentication mechanism. Before production treasury operations, replace it with authenticated admin users, role-based permissions, short-lived sessions, CSRF protection where applicable, and 2FA/WebAuthn.

No on-chain transaction is generated by ANGELA v20. A real treasury/multisig processor remains a separate controlled component.
